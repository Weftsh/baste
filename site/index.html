Baste · open source · free

Your GitHub Actions, run on your machine before GitHub gets to them

Baste runs the workflows you already have in a clean, pinned Linux VM when you push, and posts the result to GitHub as a commit status that branch protection accepts. No queue, no Actions minutes, no servers of ours.

Install

How it works

  1. git push returns right away; the pre-push hook starts the run in the background.
  2. A pending status appears on the commit for each job that runs locally.
  3. Workflows are parsed and jobs sorted by runner: ubuntu-* jobs run locally, Windows and macOS jobs are handed to GitHub.
  4. Each job boots a fresh VM from a pinned image digest (copy-on-write) and checks out the pushed commit, not your working tree.
  5. The steps run: shell steps, JavaScript, composite and Docker actions, matrices, needs, if.
  6. Each job's status flips to pass or fail, with its duration and the local run id.
  7. Require baste/<workflow>/<job> in branch protection and PRs merge on a local pass.

Why

The real workflow

Not a script you pick: the jobs in .github/workflows, in a runner-like VM.

GitHub accepts it

One commit status per job, with a stable name you can require.

Faster than the queue

Results arrive sooner than on hosted runners, and baste insights shows how much sooner.

Zero infra

Your machine does the work; GitHub is the only backend. Logs stay local.

Quick start

curl -fsSL https://raw.githubusercontent.com/weftsh/baste/main/install.sh | sh
cd your-repo
baste init          # checks VM support and gh auth, installs the hook
git push            # returns immediately; CI runs locally
baste status        # recent runs and each job's state
baste logs latest   # output per job and step (streams while running)
